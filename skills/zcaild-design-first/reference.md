# 设计规范页细则

## 页面结构

单栏、编号分块，顶部固定锚点导航。上部看效果，中部讲规则，底部给代码。7 个区块顺序不变，每块用「编号. 标题 + 一句话说明 + 右侧索引（如 VISUAL / 01）」开头：

| 区块 | 内容 |
|------|------|
| 01 色彩系统 | 按「品牌色 / 文字色 / 背景与描边 / 功能色」分组的表格（示例色块 / 色号 / 变量 / 应用） |
| 02 字体与排版 | 字体族与行高说明 + 表格（示例 / 字号 / 字重 / 应用） |
| 03 间距、圆角与阴影 | 间距尺度、圆角尺度、阴影与聚焦的可视样本，每项写数值、用途和变量名 |
| 04 基础组件 | 每个组件：名称 + 可交互 demo（含各状态）+ 标注列表 |
| 05 设计说明与使用规则 | 6 张规则卡：品牌与视觉方向、色彩使用、排版与层级、组件约束、布局与响应式、设计禁忌 |
| 06 设计变量与代码 | 由 `:root` 自动生成并按 `TOKEN_GROUPS` 分组的变量清单 + 复制按钮，无需手写 |
| 07 交付信息 | 版本、适用项目、取值来源、生成方式、确认状态；「待处理（文字可读性）」由脚本自动填写 |

05 的规则要写成可执行的约束（有数字、有边界、有禁止项），不要写空泛的形容词；这是 AI 后续写界面时最常回看的一节。新增变量前缀时，同步在脚本的 `TOKEN_GROUPS` 里登记分组。

≤900px 组件 demo 与标注上下排列，≤760px 缩小页边距。

## 必备 token

模板中的变量名是约定，换品牌时保留变量名、只改值。

**颜色**

| 变量 | 角色 |
|------|------|
| `--color-bg` / `--color-bg-hero` | 页面背景色 / 顶部氛围渐变 |
| `--color-brand-gradient` | 品牌渐变（主按钮、选中态、角标）；无渐变时设为纯色 |
| `--color-primary` / `-deep` / `-soft` / `-border` | 主色 / 按下态 / 浅底 / 描边按钮描边 |
| `--color-tag-bg` / `--color-tag-text` | 标签底色与文字 |
| `--color-danger` / `--color-success` | 错误、成功（品牌未定义时补充，并在页面标「补充」） |
| `--color-text-primary` / `-body` / `-secondary` / `-tertiary` | 标题 / 正文 / 说明与占位 / 禁用 |
| `--color-line` / `--color-line-soft` | 描边分割线 / 卡片弱描边 |
| `--color-surface-*` | 卡片、浅色面板、深色区块等面板底色 |
| `--shadow-*` / `--focus-ring` | 卡片投影、主按钮投影、聚焦外发光 |

深色主题时，文字层级可改用白色加透明度（100% / 67% / 40%），`--color-line` 用白色 16%。

**字体**：`--font-family`；`--fs-display / h1 / h2 / body / caption / mini`；`--fw-heavy / semibold / regular`；`--lh-title / body`。

**间距**：`--space-1 / 2 / 3 / 4 / 6 / 8 / 12 / 16`（4 的倍数：4–64）。组件内用 4–16，卡片间距 24，面板内边距 32，区块间距 48–64。

**尺寸与布局**：`--radius-*`、`--h-input`、`--h-button`、`--h-button-sm`、`--h-nav-item`、`--container-max`。按平台调整：移动端按钮 40–48、输入框 48–56；桌面端按钮 32–44、输入框 36–44。

**动效**：`--duration-fast / normal`、`--ease-standard`，过渡统一 150–200ms。

## 没有品牌素材时怎么定

**颜色：从一个主色推导整套**

1. 按产品气质选主色色相：企业服务/金融/工具偏蓝或青；健康/环保偏绿；美妆/生活偏粉或珊瑚；游戏/娱乐可用高饱和紫、橙。
2. 主色饱和度适中，确保白字放在主色上 ≥ 4.5；不够就压暗主色，而不是换白字为其他颜色。
3. 由主色派生（同色相，只调明度/饱和度）：
   - `-deep`：明度降 6–10%，用于按下态
   - `-soft`：明度 95–97%，用于图标底、选中浅底
   - `-border`：明度 88–90%，用于描边按钮
4. 文字层级用主色色相的深色，而不是纯灰：标题（明度 10–15%）、正文（25–30%）、说明（45–50%，须 ≥ 4.5）、禁用（65–70%）。
5. 描边与分割线：主色色相、明度 88–92%、低饱和。
6. 功能色固定选可读版本：错误 `#D92D20`、成功 `#027A48`、警告 `#B54708`（均在白底 ≥ 4.5）。

**避免「AI 默认风格」**：不要默认紫色到粉色渐变、不要满屏玻璃拟态、不要所有卡片同一个大圆角加大投影；渐变最多用于主按钮和少量强调，且只用同色相或相邻色相。

**字体**

- 中文界面：`"PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Microsoft YaHei", sans-serif`，不引入网络字体。
- 需要英文/数字有个性时，只给标题或数字加一个英文字体放在字体栈最前面，正文不变。
- 字号层级 6–7 级即可；相邻层级比例约 1.15–1.35；字重最多 3 种（常规 / 半粗 / 粗）。
- 行高：标题 1.15–1.3，正文 1.6–1.75。

## 文字可读性检查（后台运行）

页面上没有独立的对比度区块；检查由脚本在后台按 WCAG 2.1 AA 计算，只把需要用户拍板的问题用大白话写进「07 交付信息 → 待处理（文字可读性）」，并附上自动推算的建议色值（保持色相、只调明度、同时满足该变量参与的所有组合）。

- 脚本里的 `CONTRAST_PAIRS` 登记「文字色 × 背景色」组合：`[名称, 前景, 背景, 最低比值]`，前景/背景可写 token 名或色值；名称用用户能看懂的说法（如「说明文字」「主按钮文字」）。
- 新增任何文字与背景的组合（新组件、新状态），都要登记进去。
- 要求：正文 4.5；大字（≥ 24px，或 ≥ 19px 且粗体）3；禁用态豁免，不登记。
- 渐变背景按最差的色标计算；半透明颜色先叠加到背景上再算。
- 自己推导的颜色出现在待处理里，就直接采用建议色值改 `:root`，刷新到待处理显示「无」为止；交付给用户的页面里只应剩品牌方给定的颜色，由用户决定是否采用建议值。

## 组件清单

按产品挑选，常见 GUI 应用至少覆盖前六项：

1. 输入框：默认 / 聚焦 / 有值（出现清空图标）/ 错误
2. 主要按钮：常规 / 悬停 / 按下 / 不可点击
3. 次要按钮与链接：描边按钮 / 文字链接 / 弱操作（或警示）
4. 导航：顶部胶囊导航、侧边栏（桌面端）或底部标签栏（移动端），未选中 / 选中
5. 标签与角标
6. 卡片 / 列表项
7. 工具栏或操作栏：可用 / 不可用图标
8. 弹窗 / 底部弹层
9. Toast / 空状态 / 加载态
10. 开关、单选、复选

## 标注写法

每个组件旁用 `<ul class="note">` 列出，`属性：值`，同一行多个属性用全角空格分隔：

```
高度：40　宽度不固定
圆角：28，胶囊形
可点击填充色：品牌渐变色
不可点击：#FFFFFF 16%
文字字号：14
可点击字体色：#FFFFFF　不可点击字色：#FFFFFF 67%
```

规则：

- 尺寸写数字不带单位（默认 px）
- 颜色写 `色号 透明度`，或直接写 token 的中文角色名（如「品牌渐变色」）
- 每个状态都要写到：默认、悬停/按下（如有）、聚焦、禁用、选中、错误
- 标注中的值必须和 `:root` 一致；改 token 时同步改标注和颜色表

## 交互要求

- demo 使用真实元素（`input`、`button`、`nav`），禁用态用 `disabled` 属性
- 有焦点样式（`:focus-within` / `:focus-visible`）
- `prefers-reduced-motion` 下关闭过渡
- 图标按钮有 `aria-label`
