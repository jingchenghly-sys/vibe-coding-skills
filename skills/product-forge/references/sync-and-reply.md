# 推断规则、改动同步与完成回覆

## 何时推断、何时冻结

| 用户怎么给 | 做什么 |
|---|---|
| 想法 / 口述 / 笔记，没有现成草稿 | 先项目后模块：无项目根则先建 `{项目}/` 与 `概述.md`，再在 `{模块}/` 收成完整草稿。有代码则写 PRD 并改项目；无代码则写 PRD + 原型。没说的推断进对应 key，完成回覆列出。一次写完 |
| 直接给出草稿 | 原样落盘。有代码：PRD + 项目。无代码：PRD + 原型。保留用户给的名称、顺序与模块划分 |
| 已改 `结构草稿.json`，或说「按草稿同步」 | 重读磁盘上的文件。有代码：同步 PRD + 项目。无代码：同步 PRD + 原型。用户改过的 key 以磁盘为准 |
| 只改 PRD | 结构变了先回写草稿；只是规则则同步实现（有代码）或原型（无代码） |
| 又在对话里改结构 | 先改草稿再同步，并提醒下次改文件 |

两种例外（即使是用户给的草稿也做）：缺四问则补四问；旧 key `范围` 拆进 `需求` 与 `边界` 后删掉。

只有项目名和模块名都推断不出时，才问一句。能从想法推出（如「做个个人名片」→ 项目「个人名片」、第一页「个人主页」）就直接定。已在项目内则只推断模块名。

## 改动同步

| 发生了什么 | 先改 | 再改 |
|---|---|---|
| 用户给出或直接改了 `结构草稿.json` | 以新草稿为准 | PRD + 项目（有代码）或 PRD + 原型（无代码） |
| 口述改字段、选项、按钮、步骤、模块、四问、约束 | 结构草稿（提醒下次改文件） | 同上 |
| 改规则说明、校验提示、范围外说明的展开 | PRD | 项目或原型（结构不动） |
| 改间距、颜色、端上的视觉 | 项目（有代码）或原型（无代码） | 不动草稿；规则变了才改 PRD |

## 完成回覆（新建后必用）

有代码项目：

```
已写入 `{项目}/`（或 `product/`）
- 概述.md                 ← 新建项目时写入；已有则对齐
- {模块}/结构草稿.json    ← 协商入口：改这里即可同步 PRD 和项目
- {模块}/PRD.md
- 项目：{改了哪些页面 / 接口}

本次推断（不对就改草稿里对应 key）：
- …

下一步：打开结构草稿.json，先核四问（用户 / 场景 / 需求 / 边界），再改模块 / 字段 / 选项 / 操作 / 顺序；改完说「按草稿同步」。
```

无代码项目：

```
已写入 `{项目}/`
- 概述.md
- {模块}/结构草稿.json
- {模块}/PRD.md
- {模块}/原型.html

本次推断（不对就改草稿里对应 key）：
- …

原型对标：{案例A} / {案例B}（取了：布局或触控的一句话）

下一步：打开结构草稿.json，先核四问（用户 / 场景 / 需求 / 边界），再改模块 / 字段 / 选项 / 操作 / 顺序；改完说「按草稿同步」。
```

没有推断则写「本次推断：无」。有代码时省略原型对标行。无代码时对标只保留那一行。

## 完成前自检

- [ ] 四问在顶栏且过及格线；「不做」已写；页级异常只在 `异常`
- [ ] 以磁盘上的草稿为准；每个 key 在 PRD、实现（或无代码时的原型）同名同序
- [ ] 有代码：改的是项目代码；无代码：写原型前已调研 2–4 个同类案例，只取布局/触控/密度
- [ ] 草稿里的操作、空、失败、异常都能点到
- [ ] 推断已写入草稿对应 key，并在完成回覆列出
- [ ] 文本有必填/可空和长度；列表有排序、空态、条数；操作有成败（会失败时）
- [ ] 新建项目已有项目根与 `概述.md`；草稿与 PRD 在模块目录内；未把本页字段写进项目说明；第一页模块目录用页面名
