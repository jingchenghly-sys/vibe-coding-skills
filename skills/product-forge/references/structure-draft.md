# 结构草稿：四问、字段约束与示例

## 落地四问（草稿顶栏，先于 `端` / `入口`）

没说就推断，完成回覆列出。先过四问及格线，再写本页结构。

| 问 | key | 只回答 | 及格 | 不是 |
|---|---|---|---|---|
| 用户 | `用户` | 谁用、什么角色 | 具体到角色 | 端名；「用户」一词 |
| 场景 | `场景` | 何时何地为何打开 | 有触发 | 交互步骤 |
| 需求 | `需求` | 这次要做成哪件事 | 一件事 | 字段清单 |
| 边界 | `边界` | 本次范围外的事；不是谁的 | 「不做」能排除本类页面的常见膨胀 | 字段级长度/排序/空/成败；页级异常（写 `异常`） |

`边界` 用短语或 `{"不做": "…"}`，并写清「不做」。没有页级异常则省略 `异常` key。

## 字段级约束

有什么写什么。可选 key 有才写。详情、弹窗、抽屉、步骤、区块各自成 key，内部用数组保序。字段级约束写在对应 key 上。没说就推断，列入「本次推断」。超限交互见机械映射里的默填。

| 有什么 | 必须写清 |
|---|---|
| 文本 / 输入 | 必填或可空；最大长度（或「不限」） |
| 列表 / 重复项 / 多图 | 排序；最大条数（或「不限」）；空时怎样 |
| 操作 | 成功怎样；失败怎样（是否保留已填）；何时不可用 |
| 可空模块 | 空时整块不出现，还是占位 |
| 页级异常 | 写入 `异常`（链接无效、无权限等）；没有则省略该 key |

想法入口还要推断并写入：`端`、权限（谁可见/谁可操作）、提交副作用、详情用抽屉/弹窗/新页。推断匹配本页的端。

草稿用 JSON。key 用业务名。数组顺序 = 界面顺序。规则写成短语。模块目录名 = 页面/功能名。

## 示例：列表 / 管理类

有搜索和表才用。

```json
{
  "用户": "运营；按权限看本页",
  "场景": "工作台里处理待办，要快速找到一条并处理",
  "需求": "按条件筛出列表，查看详情，必要时删除",
  "边界": "不做跨页批量",
  "异常": { "无权限": "不展示对应操作" },
  "端": "管理后台",
  "入口": "模块 → 页面",
  "搜索": ["字段A", "字段B"],
  "列表": ["字段A", "字段B", "操作"],
  "排序": "新到旧",
  "空": "表内提示暂无数据",
  "相关选项": { "字段B": ["选项1", "选项2"] },
  "操作": {
    "详情": "右侧抽屉",
    "删除": "弹窗确认，不可恢复；失败留在本页"
  }
}
```

## 示例：流程 / C 端类

按用户路径拆 key。

```json
{
  "用户": "已登录用户；游客只能预览",
  "场景": "首页点发布，要把一条内容发出去",
  "需求": "选类型、填内容、预览后提交，成功回信息流",
  "边界": "游客不展示发布",
  "端": "C 端 App",
  "入口": "首页 → 发布",
  "步骤": ["选类型", "填内容", "预览", "提交"],
  "填内容": {
    "标题": "必填，最多30字",
    "正文": "可空，最多500字",
    "图片": "可空，最多9张"
  },
  "提交": {
    "成功": "回信息流并置顶本条",
    "失败": "留在本页，保留已填"
  }
}
```

```json
  "需求": "打开或关闭配置并保存",

  "入口": "设置 → 本页",
  "展示": {
    "推荐位": "开关，默认开",
    "评论": "开关，默认开"
  },

  }

```
