# 生成项目骨架（skill 产出物）

本 skill **创建/对齐新项目**时，按下面落地。根路径默认：

`~/workspace/projects/<project-name>/`

`<project-name>` 用英文 kebab-case（或用户指定的英文名）。

**前置**：用户已确认创建/初始化项目。先判断本期要哪些端，再按 `environment-setup.md` 只检测这些端要用的工具。

## 技术栈（环境初始化默认值）

| 层 | 选型 |
| --- | --- |
| 前端 `admin` | Vue 3 + Ant Design Vue（包管理默认 **npm**） |
| 前端 `web` | Vue 3。包管理默认 **npm**，项目里已有别的则沿用 |
| 后端 `server` | Go + Gin + GORM + **MySQL** |
| 部署 `deploy` | 只编排本服务自己的进程。MySQL 等基础设施不在这里起 |

用户明确改栈之前，**创建到该端时**按上表初始化。

## 目录结构

固定有根 `README.md` 和 `product/`。端只在项目需要时创建：

```text
~/workspace/projects/<project-name>/
├── .git/             # 始终有：Git 仓库
├── .gitignore
├── product/          # 始终有：项目说明 + 各页结构草稿
├── README.md         # 如何安装 / 跑起来；含已有端的栈与目录约定
├── server/           # 按需：后端 Go（Gin + GORM → MySQL）
├── web/              # 按需：网页 + H5（Vue 3）
├── admin/            # 按需：管理后台（Vue3 + Ant Design Vue）
└── deploy/           # 按需：本服务自己的 Dockerfile / compose，不含 MySQL
```

### 何时建端

| 端 | 本期需要时才建 |
| --- | --- |
| `server/` | 要 API、领域逻辑或数据库 |
| `web/` | 要用户侧网页或 H5 |
| `admin/` | 要管理后台 |
| `deploy/` | 要把本服务打成容器或编排起来 |

判断来自用户点名，或本期目标明显依赖该端。看不出来先问要哪几端，不要猜成全套，也不要先建空壳占位。以后需要某一端，再补建并按上表初始化。

`web` 与 `admin` 若都要，保持两个前端工程，除非用户明确要求合并。

### 产品信息收进 `product/`

`product/README.md` 记下本期必要信息。已知的直接写；对话和笔记里后出现的也补进去。这六项齐了就按它开工，缺项不再逐条追问：

| 项 | 写什么 |
| --- | --- |
| 用户 | 谁在用 |
| 目标 | 一句话解决什么 |
| 场景 | 在什么情况下用 |
| 范围 | 本期做 / 不做 |
| 主路径 | 走通演示的几步 |
| 端 | 本期要哪些端 |

名词、已定决策出现了，就按主题另存文件。接口、库表、目录职责、怎么跑留在对应端和根 `README.md`。已有内容合并，不覆盖用户改过的段落。

必要项有缺口时，收成**一次**选择：给出 2～3 个可执行方案，标明建议采用哪一个以及差别。例如：「本期可以按这三种走：A 只做网页；B 网页 + 接口；C 网页 + 接口 + 后台。建议 B，因为……你选哪个？」用户选定后写入 `product/` 再继续。同一件事不追问第二轮；用户没选，就按建议方案写下，并注明「按建议采用，可改」，然后开工。

### 页面结构草稿

本期要做的每一页，写 `product/<页面名>/结构草稿.json`。格式见 `structure-draft.md`。

```text
product/
├── README.md
└── <页面名>/
    └── 结构草稿.json
```

默认不写 `PRD.md`，不写 HTML 原型。改页面先改这份草稿，再改对应端。

### 各目录职责

| 目录 | 职责 | 创建该目录时至少做什么 |
| --- | --- | --- |
| `product/` | 必要产品信息与页面结构 | `README.md` 写齐用户、目标、场景、范围、主路径、端；每个要做的页面有 `<页面名>/结构草稿.json` |
| `server/` | API / 领域逻辑 | Go module、Gin 入口、GORM 连 MySQL（读 `DATABASE_URL` 或等价 DSN）、基础目录（如 `cmd/` / `internal/`，按常见 Go 习惯，保持简洁） |
| `web/` | C 端网页 + H5 | Vue 3 工程，能在本地跑起来 |
| `admin/` | 管理后台 | 独立 Vue3 + Ant Design Vue 工程骨架（与 `web` 分离） |
| `deploy/` | 本服务自己的容器 | Dockerfile，以及只含本服务的 compose。不包含 MySQL 或其他基础设施 |

## 基础设施

连接、账号和按需启动见 `shared-infra.md`。有 `server` 时 GORM 用 MySQL 驱动，连本服务自己的库。`deploy/` 不含基础设施。

## 对齐已有仓库

合并进现有内容。不删除用户已有、本期用不到的端。`product/` 里用户改过的段落不覆盖。还不是 Git 仓库就 `git init`；已是仓库则沿用，不重新初始化。`.gitignore` 同时忽略本机系统文件。提交时机见 `SKILL.md`。
